# Инвестиционный опросный лист

Интерактивное веб-приложение для сбора параметров инвестиционного проекта
и автоматического расчёта ключевых финансовых показателей: выручки, затрат,
EBITDA, чистой прибыли, потребности в кредитовании, NPV, IRR, PI и срока
окупаемости.

## Возможности

- Семь разделов опросного листа: **A** — общие данные, **B** — средства
  производства (CapEx), **C1** — прямые затраты, **C2** — косвенные
  затраты, **D** — административно-хозяйственные расходы, **E** — продукты
  и услуги, **F** — персонал, **G** — параметры финансирования.
- Учёт сезонности (зима/весна/лето/осень) и темпов роста для продуктов,
  затрат и зарплат.
- Автоматический расчёт необходимого кредита, графика погашения и
  процентных платежей по ставке из раздела G.
- Расчёт инвестиционных метрик: NPV (ставка дисконтирования 16%), IRR
  (методом бисекции), PI и срока окупаемости.
- Выгрузка результатов в Excel (xlsx) и графики на Chart.js.

## Стек

- **Backend:** Node.js 20 + Express 4, единственная конечная точка
  `POST /calculate`.
- **Frontend:** ванильный HTML/CSS/JS в `public/`, Chart.js и
  xlsx-js-style через CDN.
- **Запуск/деплой:** `npm start` локально, конфигурация Replit в `.replit`.

## Быстрый старт

```bash
npm install
npm start
```

Сервер слушает порт `5000` (переопределяется через переменную окружения
`PORT`). Откройте `http://localhost:5000` в браузере.

## API

### `POST /calculate`

Принимает JSON со всеми разделами опросного листа и возвращает рассчитанные
ряды по годам и сводные метрики.

**Запрос (упрощённо):**

```json
{
  "A": { "horizon": 6 },
  "B": [ { "date": "январь 2026", "amount": 1000000 } ],
  "C1": [ { "product": "...", "amountPerUnit": 100, "growth": 5 } ],
  "C2": [ { "startDate": "январь 2026", "amount": 50000, "periodicity": "ежемесячно", "growth": 5 } ],
  "D":  [ { "startDate": "январь 2026", "amount": 30000, "periodicity": "ежемесячно", "growth": 5 } ],
  "E":  [ { "product": "...", "startDate": "март 2026", "price": 500, "quantity": 100, "growth": 10, "winter": 80, "spring": 100, "summer": 120, "autumn": 100 } ],
  "F":  [ { "hireDate": "январь 2026", "salary": 80000, "count": 2, "growth": 7, "type": "постоянный" } ],
  "G":  { "creditRate": 9 }
}
```

**Ответ:**

```json
{
  "years": [2026, 2027, ...],
  "revenue": [...],
  "quantity": [...],
  "directCosts": [...],
  "indirectCosts": [...],
  "adminCosts": [...],
  "payroll": [...],
  "insurancePremiums": [...],
  "investments": [...],
  "ebitda": [...],
  "netProfit": [...],
  "financing": [...],
  "principalRepayment": [...],
  "interestRepayment": [...],
  "cashFlow": [...],
  "cashCumulative": [...],
  "requiredLoan": "...",
  "npv": "...",
  "irr": 0,
  "pi":  "...",
  "paybackPeriod": "..."
}
```

Денежные ряды возвращаются в **тысячах рублей** (значения делятся на 1000).
Даты передаются строкой вида `"месяц год"` на русском (например,
`"январь 2026"`).

## Разработка

- Внутри кода (имена, комментарии, коммиты, правила Cursor) — английский.
- Пользовательские тексты, тексты разметки и доменная терминология —
  русский.
- Любое изменение бизнес-логики или контракта `/calculate` фиксируется
  записью в `CHANGELOG.md` в тот же коммит.
- Правила Cursor-агента лежат в `.cursor/rules/` и применяются
  автоматически: они обеспечивают глобальные конвенции, ведение журнала
  изменений и поддержку этого README.

### Автодеплой через GitLab CI/CD

В репозитории используется `.gitlab-ci.yml`: при `push` в ветку `master`
GitLab Runner подключается к серверу по SSH, доставляет изменения, ставит
прод-зависимости и перезапускает приложение через PM2.

Нужно добавить переменные CI/CD в GitLab (`Settings` → `CI/CD` → `Variables`):

- `SSH_PRIVATE_KEY` — приватный ключ для SSH-доступа к серверу.
- `SSH_HOST` — хост сервера (IP или DNS).
- `SSH_USER` — пользователь SSH.
- `DEPLOY_PATH` — путь на сервере, куда деплоится проект.
- `PM2_APP_NAME` — имя процесса в PM2 для `restart/start`.

Что делает pipeline:

1. Запускается только для `push` в `master`.
2. Копирует проект на сервер через `rsync` (без `.git` и `node_modules`).
3. На сервере выполняет `npm ci --omit=dev`.
4. Обновляет PM2 до актуальной версии и выполняет `pm2 update`.
5. Делает `pm2 restart <PM2_APP_NAME>` или первый `pm2 start`, затем `pm2 save`.

## Агенты и правила

В проекте настроен набор Cursor-правил, которые описывают ролевую модель
работы агента и фиксируют операционные конвенции. Все правила
применяются автоматически (`alwaysApply: true`).

### Ролевая модель

Любой запрос проходит через короткий цикл из двух ролей:

1. **Lead** — валидирует задачу по чек-листу (одна цель, все входы,
   отсутствие конфликта со scope/контрактом `/calculate`/финансовыми
   константами/языковой политикой, конкретные критерии приёмки), при
   неясности задаёт уточняющие вопросы, декомпозирует задачу и передаёт
   её Developer-Tester'у явным брифом. Самостоятельно код не пишет.
2. **Developer-Tester** — выполняет задачу в две жёсткие фазы:
   - **Develop** — минимальная реализация под критерии приёмки, без
     попутных рефакторов и переименований; уважение существующих
     хелперов (`parseRussianDate`, IRR-границы, тысячи рублей,
     английский в коде / русский в UI); симметричные правки
     `server.js` ↔ `public/script.js` при изменении контракта.
   - **Test** — верификация по чек-листу: критерии приёмки, целостность
     контракта, численная адекватность финансовой математики, краевые
     случаи, языковая политика, скоуп правок, отсутствие новых
     зависимостей, чистые линты, smoke-run при возможности и
     bookkeeping (`CHANGELOG.md` / `README.md`).

После отчёта Developer-Tester'а Lead принимает работу и резюмирует
результат пользователю.

### Краткие глобальные правила

- **Scope discipline (наивысший приоритет).** Делать только то, что
  попросили. Никаких единоличных решений: при двусмысленности или
  значимом trade-off — задавать уточняющий вопрос. Никаких правок
  «раз уж я здесь».
- **Языковая политика.** Код, идентификаторы, комментарии, коммиты,
  правила Cursor и `CHANGELOG.md` — английский. UI, доменные тексты,
  `README.md` — русский. Русские названия месяцев и сезонов
  (`winter`/`spring`/`summer`/`autumn`) — часть API-контракта, не
  переводятся.
- **Контракт `/calculate`.** Любое изменение формы запроса/ответа
  применяется одновременно в `server.js` и `public/script.js`.
  Финансовые константы (страховые 30%, чистая прибыль 80% EBITDA,
  ставка дисконтирования 16%) считаются инвариантами — изменение
  требует записи в `CHANGELOG.md` и, при пользовательском эффекте,
  обновления `README.md`.
- **Журнал изменений.** После каждой содержательной правки —
  запись в `CHANGELOG.md` под `[Unreleased] - YYYY-MM-DD` в формате
  Keep a Changelog с фокусом на «почему», а не на «что». История
  только дополняется.
- **README по умолчанию.** При изменении команды запуска,
  зависимостей, структуры, формы `/calculate` или пользовательских
  фич синхронизируется этот файл.
- **Безопасность.** Никаких секретов, `.env`, `zipFile.zip` в
  коммиты; никаких деструктивных git-команд и автокоммитов без
  явного запроса.
